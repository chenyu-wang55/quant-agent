## 1. 目标与当前基线

先让系统的执行控制、数据与分析可信，再评估新依赖和 AI 的增量价值。达到的目标是：安全控制跨进程有效、输入数据可追溯、研究结果可复现，并具备受监督纸交易的运行证据。

PIT（point-in-time）指在历史决策时点已经可获得的数据；OOS指未用于训练或调参的样本外数据；XNYS指纽约证券交易所交易日历。本文文件路径以项目 `/Users/chenyu/Desktop/auto/quant/quant-agent` 为根，质量命令从该目录执行。

|---|---|---|
| 运行环境 | API 已统一使用项目 `.venv` 和锁定依赖；185 项测试及静态检查通过 | 保持同一环境，补充此次发现的遗漏场景；已有测试通过不能代替新问题验收 |
| 交易状态 | kill switch 开启，Autopilot 禁用，模式为 paper，Worker 未运行 | 开发与研究阶段保持此状态；纸交易观察窗口使用专门的运行流程 |

以下为**拟定AI验收目标**，在查看最终测试集结果前冻结；它们是质量目标，不是策略收益承诺：

| 指标 | 拟定目标与测量方式 |
|---|---|
| 固定样本 | 至少200条授权、脱敏且人工标注的新闻/公告/财报片段；至少60条冻结测试样本。按发行人/事件/时间隔离重复与近似样本，覆盖正常、负面、缺失、冲突和指令注入 |

| 事实与时间校验 | 对发布结果，关键事实引用覆盖率100%；无法由输入证实的数值、决策时点之后的证据均为0。分别统计原始错误与校验器拦截率，不能靠拒绝全部输出达标 |
| 可用性与成本 | 测试集有效且通过校验的输出覆盖率≥90%；记录p50/p95延迟、单条及整批费用。开始付费试验前配置数值预算和超时，超过上限无新增付费请求 |

样本量只是初始门槛，报告保留分母、置信区间与失败分布，不能将小样本结果外推为全市场可靠。事实抽取留存原文片段、来源、publication/available时间、输入指纹、实际模型标识、提示词/Schema版本、原始响应或可检索归档引用、token/费用、延迟与校验结果；仅存响应哈希不足以复核。

A3估算包含已有可读样本的初步标注与评估，假设标注工作不超过1人日；数据搜集、长财报逐页标注或多轮专家复核超出此条件时另估，不把金标集当作已经存在。费用限制在请求前按最大token数预留额度，额度不足不发请求；已发出的请求仍可能完成并产生费用。

历史研究只能使用当时已可用的输入，避免实时网页和模型未来知识混入。对历史样本拒绝无输入证据的模型事实；模型输出被证据约束也不能证明完全消除了未来信息风险，收益验证优先使用当时归档抽取并辅以前向纸交易。评估保存在仓库或独立工具中；依据[官方停用公告](https://developers.openai.com/api/docs/deprecations)，不把新方案绑定即将停用的Evals平台。

## 7. 阶段⑤：把“分数”与“胜率”分开，验证增量收益

| ID / 工作量 | 交付 | 验收证据 |

| Q1 / 1–2人日 | 独立校准器及`signal_strength`/`calibrated_probability`语义；定义概率对应的目标、持有期与成本口径，无校准结果时不展示胜率 | 校准只拟合训练/验证区间，不接触最终样本外标签；报告Brier/ECE、可靠性分组及样本数；版本和目标可追溯，回归比较规则基线，不能把现有统计输出当作已应用校准 |
| Q2 / 2–3人日 | 在[回测引擎](/Users/chenyu/Desktop/auto/quant/quant-agent/services/research/backtest_engine.py)等模块增加多轮滚动训练/验证/OOS；隔离跨边界的重叠持仓标签，记录全部参数搜索 | 预先固定窗口、最少轮数、参数候选和最终留出区间；purge/embargo按标签结束时间与持有期定义；每轮只用此前数据，最终留出集不反复调参 |
| Q3 / 1–2人日 | 同数据、成本和风险约束下做规则基线、校准、AI事件特征的逐项对比；交易成本1×/1.5×/2×、延迟和流动性压力场景 | 输出逐轮与合并OOS、交易明细、回撤、换手和市场状态指标；至少3轮可行OOS窗口，否则标记证据不足。新特征无稳定增益则保留规则基线，不强行上线 |

滚动研究的拟定初始配置为训练36个月、校准/验证6个月、OOS6个月、每次前移6个月；研究区间末尾12个月作为最终留出，滚动调参不使用它。至少3轮OOS，按持仓标签结束时间隔离边界。数据长度不足时报告证据不足；修改窗口必须先建立新研究版本，再开始评估。

候选采用条件在Q3前冻结：新增AI/排序特征须满足既有样本外风险收益门槛，合并OOS扣成本期望收益高于基线、最大回撤不高于基线，至少三分之二滚动窗口期望收益不低于基线；1.5倍与2倍成本下合并期望收益仍为正，并在未使用的最终留出区间确认方向一致。单纯概率校准还要求OOS Brier与ECE均不劣于冻结的概率基线且至少一项改善；默认基线是只用训练区间同一目标的发生频率构造的常数概率，不能把规则强度直接当作概率。报告比较的置信区间，区间无法区分改善与噪声时保持旁路研究。上述为拟定研究口径，不在看到结果后挑选采用标准。

保留[现有实盘候选验收阈值](/Users/chenyu/Desktop/auto/quant/quant-agent/docs/optimization_acceptance.md)：OOS交易数≥100、最大回撤≤15%、Profit Factor≥1.20、Sharpe≥0.8、payoff ratio≥1.5、扣成本期望收益>0、单标的≤10%、行业≤30%。上述阈值用于与当前实现口径一致的样本外结果；多轮结果同时报告各轮与合并值，100笔不是每轮重复要求。收益为正也需检查样本不足和过度搜索，不能只用合并均值隐藏失败阶段。

校准或模型改变策略行为时，为候选生成独立策略配置ID/版本与回测记录；说明当前代码是否识别该变更。未通过匹配strategy ID和dataset fingerprint的验收记录，禁止用其他版本的合格结果授权实盘。

开发期间锁定且Autopilot关闭。P1交付以下明确顺序，先在paper环境演练，再用于每日监督窗口：

1. Worker保持停止，设置模式paper、paper账户/端点和真实数据配置，确认live runtime allow未开启；全局锁仍开启，Autopilot仍关闭。
2. 运行 `.venv/bin/python scripts/preflight.py --target paper --require-kill-switch enabled`，全部通过后，留存锁定状态下的预检报告。
3. 在XNYS常规时段，由监督运行者启用已冻结的paper策略和自动执行，确保每日审批/买卖预算已配置，再释放全局锁；此时Worker仍未启动。
4. 运行 `.venv/bin/python scripts/preflight.py --target paper --require-kill-switch disabled`；检查持久化策略的运行就绪、快照、日损、对账、价格与组合风控门槛。全部通过才启动监督窗口的Worker；失败立即重新锁定并关闭自动执行。
5. 窗口结束或出现阻断，先开启全局锁，关闭自动执行并停Worker；保存预检、运行、券商状态和在途请求记录，再确认锁定状态。

paper计日沿用明确的合格证据机制，并在P1补齐策略/执行版本签名：100%建模标的行情与基本面覆盖、行情年龄不超过当前默认4320分钟、PIT来源与指纹已验证、日损门槛通过、按冻结策略要求的新鲜对账通过、常规时段、paper模式、自动执行已实际评估且没有执行错误。价格漂移、组合风险和审批约束继续逐单生效。更具体的日损金额/比例、对账时效与订单/审批预算在paper清单中沿用当前配置并冻结，不降低门槛凑天数。

没有可批准信号的日期仍可合格，但必须确实评估执行且所有必要门槛通过；20天无订单只能证明观察流程运行，不能证明成交/部分成交/保护更新链路已验证。这些链路另用paper故障与生命周期场景提供证据。故障演练造成失败的当天不计合格日，必要时延长观察。

纸交易验收包与实盘启用决策分开。该阶段完成后默认继续paper；实盘需系统所有者单独决定，复核匹配的回测、账户、对账、保护、风险限额与纸交易证据。

## 9. 共用发布、验证和回滚流程

| 失败类型 | 回退方式 |
|---|---|
| 代码/依赖不兼容 | 恢复上一验收提交与锁文件，在独立环境重建并验证；回退版本也需通过schema兼容检查 |

| 迁移失败 | 停止全部写入并保持交易锁；生产维护窗口恢复经过验证的备份及其兼容代码，检查完整性、控制状态和审计差异；不假定downgrade一定无损 |
